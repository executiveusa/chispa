Chispa V3 implementation report

Product architecture

Implemented: Home / Lists / Search / Projects / More. Priority, category, list and project are separate concepts. Solar lives inside Projects with its own Overview, Checklist, Wiring, Suppliers and Documents tabs.

Core behavior

Implemented: functional Add, list/project CRUD, Need/Nice filtering, cross-list priority views, offline IndexedDB autosave, v1 migration, JSON/CSV/PDF, read-only share links, WhatsApp summaries, supplier CRUD, local navigation, marketplace search links, saved-offer landed-cost comparison, spending fields, urgency, assignment, budget caps, target dates, receipts/warranty/serial/return references.

Currency

Each amount remains in its original currency. Chispa derives the second currency from one rate. The bundled fallback is 17.3973 MXN/USD, dated 2026-07-22 and labeled Banco de México FIX. Users can update the rate manually; the timestamp/source changes accordingly.

Truthfulness

Starter solar amounts are labeled planning estimates, not verified live market prices. Chispa opens marketplace searches and compares offers the user saves; it does not claim automatic retailer scraping.

External blockers

Not yet connected: editable household sync and cloud file uploads require the user's self-hosted Supabase endpoint/public configuration. The exact approved hero binary also remains unavailable to the repository writer; `/chispa-hero.webp` is supported and a neutral fallback is shown meanwhile.
